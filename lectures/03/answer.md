# 第3回 解答

## 演習

* 第1回（素のLLM）とエージェントの回答の違い：
* 素のLLM（第1回）は自身の事前知識のみで回答しますが、エージェントは `search_glossary` ツールを使って用語集を参照するため、講座で定義された正確な表現や「（関連する回：第2回）」といったメタ情報を含めて回答するようになりました。


* `--trace` で見えたツール呼び出し（ツール名と引数）：
* 1回目：`search_glossary({'query': 'LoRA QLoRA'})`
* 2回目：`search_glossary({'query': 'LoRA'})`, `search_glossary({'query': 'QLoRA'})`（※宿題の検証結果を含む）


* 1つの質問での LLM 呼び出し回数（`requests`）：
* `requests: 2` （モデルがツールを選択・実行し、その結果を受け取って最終的な回答を生成するため、1つの質問に対して2回LLMが呼ばれています）


* 追加したツールと、docstring に書いた説明：
* ツール名：`make_quiz(lecture: int)`
* docstring：指定された講義回の用語集からランダムに1つ選び、確認用の問題と答えをJSON形式の文字列で返す。確認問題を求められたときに使用する。



## 宿題

* 取り組んだレベル：基礎
* やったこと：
* `app/tools.py` の `search_glossary` の docstring（「query には調べたい用語を1つだけ入れる」という指示）を「まとめて入れる」に変更し、同じ質問（"LoRAとQLoRAの違いは？"）を `--trace` 付きで実行して、ツールの呼ばれ方や引数がどう変わるかを比較しました。


* 結果：
* 変更前は `query` に `'LoRA QLoRA'` とまとめて1回で検索していたのに対し、docstringの制約を変更または調整したことで、モデルが `LoRA` と `QLoRA` のそれぞれのキーワードに分けて2回別々に `search_glossary` を呼ぶ挙動に変化しました。それに伴い、プロンプトトークン数やツール呼び出し回数（`tool_calls`）が増加しました。


* 気づき・疑問：
* ツールの docstring に書かれている説明文（制約や引数の渡し方）が、LLMのパラメータ選択やクエリの分解方法にダイレクトに影響を与えていることが `--trace` を通して非常に分かりやすく確認できました。
